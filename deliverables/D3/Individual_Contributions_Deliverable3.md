**Ethan Yang**, CI/CD and development environment
> Set up continuous integration with a GitHub Actions workflow (`.github/workflows/ci.yml`) that runs on every pull request and every push to main. It has three parallel jobs: backend typecheck and tests, frontend lint and production build, and database migration and seed tests. The backend tests run against an in-memory database built from `supabase/migrations` and `supabase/seed`, so CI never touches the hosted Supabase. Added concurrency cancellation and job timeouts so stale or hung runs don't hold runners. Because secrets can't be added to the org repo, set up continuous deployment through a scheduled workflow (`sync-fork.yml`, every 15 minutes) that syncs main into Jason's fork, which Vercel then auto-deploys, following the TA-endorsed fork approach on Piazza. Wrote `ENVIRONMENT.md` covering local setup, environment variables for the backend, frontend and model service, how deployment works, and how to run the CI checks locally, and added the missing frontend `.env.example`. Implementation: [CI workflow commit fd2f42d](https://github.com/csc301-2026-f/25-Merto/commit/fd2f42d), [fork sync PR #20](https://github.com/csc301-2026-f/25-Merto/pull/20), [ENVIRONMENT.md PR #24](https://github.com/csc301-2026-f/25-Merto/pull/24), and [frontend env example PR #25](https://github.com/csc301-2026-f/25-Merto/pull/25).

**Rachel Pham**, calendar interface, appointment creation & tracking
> Implemented the manager and rep calendar for viewing, creating, and editing appointments, including manager filters by rep and a queue for appointment requests awaiting confirmation (US9). Managers are able to see all appointments of all reps across the store. **Vic Ying**, scenario checks (backend and manager page)
> Built the scenario check feature (US13), where a General Manager runs a predefined scenario and sees whether an agent did what the store expects. A run builds a deal at a fixed point in time inside a database transaction, lets an agent act through a few tools (reply, create a to-do, request a visit, or do nothing), scores the result with eleven deterministic checks that also reuse the US5 evaluation rules, and rolls the transaction back so nothing is saved. Created seven scenarios from the Merto brief (Deals J, K, C, I, E, L and A), a scorecard with a step-by-step run log, a comparison of two agents, and an interface that lets an outside agent read a scenario and post its tool calls to be scored. The tools obey the store's AI mode (off blocks a reply, draft-only keeps a draft). Added two rule-based sample agents, one that follows the store rules and one that makes the mistakes the brief warns about, and a manager Scenarios page to run them and read the scorecards. Wrote 13 automated tests and documented the endpoints and checks in `backend/README.md`. Implementation: [Scenario checks PR #18](https://github.com/csc301-2026-f/25-Merto/pull/18).
